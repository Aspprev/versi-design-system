# Guia de uso

Use as entradas públicas do pacote e tokens semânticos. Regras de negócio, chamadas de API, autenticação e navegação pertencem à aplicação consumidora.

## Princípios de composição

- Comece por um componente ou padrão existente.
- Prefira tokens semânticos como `--surface-page`, `--content-primary`, `--border-default` e `--focus-ring`.
- Documente a API e os estados necessários para o consumidor.
- Importe de `@aspprev/versi-ds` ou dos subcaminhos públicos documentados.
- Confira o comportamento em celular, tablet e desktop.

## Responsividade

Use `useBreakpoint` quando a decisão depende da viewport inteira. Use
`useContainerBreakpoint` quando depende da largura real disponível para um
componente, como em uma tabela ao lado de um menu ou em um painel dividido.

```tsx
import { useContainerBreakpoint, useBreakpoint } from "@aspprev/versi-ds/core";

const viewport = useBreakpoint();
const content = useContainerBreakpoint(containerRef);
```

O contrato de conteúdo usa `--content-max-width` e
`--content-gutter-inline`. Os tokens são referências para composição; o DS
não impõe header, menu, shell ou largura de uma jornada de produto.

## Evolução da API

Prefira propriedades opcionais antes de considerar uma mudança incompatível. Preserve atributos HTML nativos, documente os modos controlado e não controlado e defina nomes acessíveis e estados de erro.
