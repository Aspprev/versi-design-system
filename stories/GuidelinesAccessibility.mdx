# Accessibility

Use the VERSI components as part of an accessible interface from the first interaction. The component API should expose the information that assistive technologies need instead of relying on visual context alone.

## Required checks

- Every interactive control has an accessible name and a visible focus indicator.
- Keyboard users can reach, operate and leave every interactive state without a pointer.
- Validation errors are associated with their field and are announced when the interaction requires it.
- Loading, success, empty and error states communicate their status without depending on color alone.
- Text and controls remain usable at 200% and 400% zoom and at narrow viewport widths.
- Motion-sensitive transitions honor the consumer's reduced-motion preference.
- Focus emphasis is available through `data-focus-emphasis="strong"` and link emphasis through `data-link-emphasis="underline"`; consumers may opt out of individual links with `data-no-accessibility-underline`.

## Storybook workflow

Use the toolbar to compare light and dark schemes, high contrast, font scale and reduced motion. Use the Accessibility panel together with keyboard navigation; the automated visual suite also runs Axe against the priority scenarios.

When adding a story, include at least one realistic state with a label, an error or status message when applicable, and a keyboard interaction for composite controls.
